# LocalFileSorter

Настольная утилита для быстрой раскладки файлов по подпапкам-«бакетам». Приложение показывает один файл за раз с превью, вы кликом по цвету назначаете ему бакет и переходите к следующему. На диске ничего не двигается, пока вы явно не подтвердите перенос.

.NET 9, SFML 3.0, весь интерфейс отрисован вручную. Windows x64 / ARM64.

## Как это работает

1. Перед открытием окна приложение спрашивает в консоли **исходную папку** (сканируется рекурсивно, до коммита только читается) и **папку назначения**.
2. Подпапки первого уровня папки назначения становятся бакетами. Приложение их никогда не создаёт, не переименовывает и не удаляет — создайте папки в проводнике и нажмите `Reload mapping`.
3. Каждому бакету выдаётся цвет из палитры. Клик по свотчу назначает активный файл этому бакету и переводит к следующему неназначенному; повторный клик по тому же свотчу снимает назначение.
4. `Sort` открывает подтверждение и выполняет реальные перемещения. При конфликте имён файл получает суффикс: `name (1).ext`.

Интерфейс мышиный: назначение, навигация по очереди, выбор цвета, `Undo`, `Reload mapping` — всё кнопками. Исключение — прокрутка превью, которая также работает стрелками и `WASD`.

## Превью

| Модуль | Расширения |
|---|---|
| Текст | `.txt` `.md` `.log` `.json` `.xml` `.csv` `.yml` `.yaml` `.ini` `.cfg` `.bat` `.c` `.cpp` `.cs` `.css` `.go` `.h` `.hpp` `.html` `.java` `.js` `.jsx` `.php` `.ps1` `.py` `.rb` `.rs` `.sh` `.sql` `.toml` `.ts` `.tsx` |
| Изображения | `.png` `.jpg` `.jpeg` `.bmp` `.gif` `.tga` `.psd` `.hdr` `.pic` |

В очередь попадают только файлы, которые берёт хотя бы один модуль превью. Остальные считаются в строке `N hidden (unsupported)`.

Новый тип файлов добавляется реализацией `IPreviewProvider` и регистрацией в `PreviewRegistry`.

## Запуск

Требуется .NET 9 SDK. Команды выполняются из папки решения.

```
dotnet run --project src/LocalFileSorter
```

Нужен интерактивный терминал: обе папки запрашиваются в консоли до открытия окна. `Enter` принимает путь из прошлой сессии, `q` выходит.

Тесты:

```
dotnet test
```

## Сборка в один .exe

```
dotnet publish src/LocalFileSorter/LocalFileSorter.csproj `
  -c Release `
  -r win-x64 `
  --self-contained true `
  -p:PublishSingleFile=true `
  -p:IncludeNativeLibrariesForSelfExtract=true `
  -p:IncludeAllContentForSelfExtract=true `
  -p:EnableCompressionInSingleFile=true `
  -p:DebugType=none `
  -o publish/win-x64
```

Результат — `publish/win-x64/LocalFileSorter.exe` (~37 МБ) и ничего больше в папке. Для ARM64 замените `-r win-x64` на `-r win-arm64`. Флаги `IncludeNativeLibrariesForSelfExtract` и `IncludeAllContentForSelfExtract` обязательны: без них рядом с exe останутся нативные DLL и папка `assets/`. .NET на целевой машине не нужен.

## Структура

```
src/LocalFileSorter/
  Common/      домен и сервисы, без зависимости от SFML
  Previews/    модули превью
  Ui/          панели, виджеты, рендеринг, ввод
  App/         консольный старт и композиция
assets/
  fonts/       Noto Sans (интерфейс), DejaVu Sans Mono (текстовые превью)
  i18n/        каталоги локализации, в v1 только en.json
  themes/      скины: flat-dark, classic-9x, xp, terminal
tests/
```

Все строки интерфейса берутся из каталога локализации, в коде их нет.

## Темы

Скин — папка с файлом `theme.json` (и, при необходимости, шрифтами рядом). Он задаёт не только палитру, но и способ отрисовки поверхностей: заливка, градиент, фаска, рамка, скругление. В комплекте четыре скина:

| Скин | Вид |
|---|---|
| `flat-dark` | текущий тёмный плоский интерфейс, используется по умолчанию |
| `classic-9x` | серый Windows 9x: жёсткие фаски 2 px, синие заголовки, без скруглений |
| `xp` | Luna: синие градиентные заголовки, скруглённые кнопки, Tahoma |
| `terminal` | зелёный фосфор на чёрном: моноширинный интерфейс, острые углы, тонкие рамки |

Выбор — поле `theme` в `settings.json`; значение применяется при следующем запуске. Скин ищется сначала в `themes/<имя>/` рядом с `.exe`, затем в `assets/themes/<имя>/`. Свои скины кладите в папку `themes/` рядом с исполняемым файлом: она не перезаписывается при обновлении и работает в том числе при сборке в один `.exe`, когда содержимое `assets/` распаковывается во временную папку.

Файл может быть неполным — всё неуказанное берётся из встроенных значений (они совпадают с `flat-dark`). Значения, которые приложение не смогло разобрать, перечисляются в stderr при старте; отсутствующий или битый файл скина не мешает запуску.

Шрифты объявляются как `"font": { "ui": "Tahoma.ttf" }` и ищутся в папке скина, затем в `assets/fonts/`, затем среди системных шрифтов Windows.

## Настройки

Приложение портабельное: за пределы своей папки оно не пишет ничего. Единственный создаваемый файл — `settings.json` рядом с `.exe` (последние папки, размер окна, язык, тема). Файл можно удалить, значения вернутся к умолчанию. Цвета бакетов не сохраняются и раздаются заново при каждом запуске.

Если папка приложения недоступна для записи (например, запуск с read-only носителя), настройки живут только в памяти текущего сеанса, а при выходе в stderr выводится предупреждение — на работу это не влияет.

Записи за пределами папки приложения происходят только туда, куда пользователь сам указал: перемещение файлов в бакеты внутри выбранной папки-назначения и временный файл-проба (создаётся и сразу удаляется) для проверки прав на запись в корень.
